## 2. Skill 4 v1 4 模块详情

### 2.1 模块 1: 谈判策略生成器 (PRD § 2.1)

**API 端点**: `POST /api/skill4/strategies`

**核心函数**: `generate_strategies(case, config) -> List[NegotiationStrategy]`

**输入**:
- 律师输入: 案件类型 + 违约方 + 期望结果 + 对方角色 + 案件事实
- 9 案件类型: contract_dispute / tort / family / equity / ip / labor / admin_review / settlement / cross_border_trade
- 3 违约方: self / other / neutral
- 3 期望结果: conservative / moderate / aggressive
- 3 对方角色: lawyer / party / judge

**输出**:
- 3 套策略 (按上下文重排优先级):
  - **保守策略**: 最小化风险, 优先维持现状, 争取小让步
  - **中等策略**: 平衡风险与收益, 争取中等让步
  - **激进策略**: 最大化收益, 接受较大风险, 争取大幅让步
- 每套策略附带:
  - **胜诉率预测**: 禁用"必胜", 用百分比 + 案例统计 (复用 W11 类案界面语言规范)
  - **建议谈判话术**: 律师可复制使用 (中英双语)
  - **法条引用**: 根据 case_type 自动选择 (民法典/公司法/CISG 等)
  - **优先条款**: 根据 case_type 给出 3-4 个优先协商条款
  - **风险等级**: low / medium / high

**关键设计**:
- 上下文感知排序:
  - 自己违约 → 保守优先
  - 家庭 / 劳动 / 行政复议 → 保守优先 (避免激化)
  - 公司股权 / 跨境贸易 → 中等优先 (避免激化股东关系 / 跨境诉讼成本高)
- 跨境自动切换法条 (CISG/UNCITRAL/PICC)
- 中英双语话术模板

**示例调用**:
```python
case = NegotiationCase(
    case_id="C-CON-001",
    case_type=NegotiationCaseType.CONTRACT_DISPUTE,
    breach_side="other",
    amount_cny=500_000,
    desired_outcome="moderate",
    opponent_role=OpponentRole.LAWYER,
    case_facts="被告逾期支付货款 50 万元",
    lawyer_id="L001",
)
strategies = generate_strategies(case, NegotiationEngineConfig())
# 返回 3 套策略: [conservative, moderate, aggressive]
```

### 2.2 模块 2: 模拟对方 3 角色 (PRD § 2.2)

**API 端点**: `POST /api/skill4/simulate-opponent`

**核心函数**: `simulate_opponent(case, role, round_num) -> OpponentSimulation`

**输入**: 案件详情 + 对方角色 + 谈判轮次

**输出** (3 角色 × 5 轮 = 15 套模板):

| 角色 | 关注字段 | 模板数 | 应用场景 |
|------|----------|--------|----------|
| **LAWYER** (对方律师) | legal_basis + tactic | 5 | 庭审前演练, 谈判前准备 |
| **PARTY** (对方当事人) | psychology_hint + tactic | 5 | 民事纠纷, 当事人主导谈判 |
| **JUDGE** (法官) | legal_basis + tendency | 5 | 庭审前预测法官倾向 |

**5 轮模板设计**:
- 第 1 轮: 初始立场 + 试探
- 第 2 轮: 反驳 + 抗辩
- 第 3 轮: 直接亮底牌
- 第 4 轮: 施压 + 让步请求
- 第 5 轮: 妥协 + 终止谈判

**关键设计**:
- 多轮演练确保每轮回应不同 (避免重复, 测试用例 `test_simulate_multi_round` 验证 5 轮至少 3 个不同回应)
- PARTY 角色独有 psychology_hint 字段 (当事人更关注心理 + 情绪)
- JUDGE 角色独有 tendency 字段 (法官视角更关注法条 + 裁判倾向)

### 2.3 模块 3: 谈判风险预警 5 类型 (PRD § 2.3)

**API 端点**: `POST /api/skill4/detect-risk`

**核心函数**: `detect_real_time_risk(text, risk_type) -> RiskAlert`

**5 类型正则匹配**:

| 类型 | 严重度 | 触发场景 | 正则 pattern 数 |
|------|--------|----------|----------------|
| **CONCEDE** (让步过度) | high | "好的, 按您说的 100% 全额支付" | 4 |
| **EVIDENCE_MISS** (漏证据) | high | "抱歉, 没注意到这份证据" | 3 |
| **DEADLINE_MISS** (错过期限) | high | "今天已过举证期限" | 3 |
| **EMOTIONAL** (情绪失控) | medium | "你胡说! 不讲道理!" | 5 |
| **INFO_LEAK** (底牌泄露) | high | "我们的底线是 30 万" | 4 |

**输出**: `RiskAlert(triggered, matched_keywords, severity, description, suggestion)`

**关键设计**:
- 每个类型 3-5 个正则 pattern (避免单一 pattern 误判)
- matched_keywords 字段记录触发的具体关键词 (便于律师事后分析)
- suggestion 字段给出处置建议 (立即暂停 / 重新评估 / 申请延期 等)
- 安全文本 (无违规) 不触发任何 alert (测试 `test_safe_text_no_alert` 验证)

### 2.4 模块 4: 谈判复盘报告 (PRD § 2.4)

**API 端点**: `POST /api/skill4/debrief`

**核心函数**: `build_debrief_report(case_id, lawyer_id, trajectory, config) -> DebriefReport`

**输入**: 谈判轨迹 (5 维度评分 + 关键节点 + 风险点)

**输出**: 复盘报告 ~5KB

**5 维度评分** (复用 W12 doc_workflow 4 文书风险标注 + W15 Skill 3 v2.0 prompt 5 维度深度推理):
- 事实 (facts): 谈判内容与事实证据吻合度 (0-1)
- 法律 (legal): 谈判策略与法律框架吻合度 (0-1)
- 主张 (demand): 谈判诉求合理性 (0-1)
- 时效 (timing): 谈判时间节奏 (0-1)
- 后果 (consequence): 谈判结果的预测后果 (0-1)

**复盘报告字段**:
- scores: 5 维度评分 (clamp 0-1)
- avg_score: 平均分
- key_clauses: 关键节点 (自动从 trajectory 提取)
- risk_points: 风险点 (自动从 trajectory 提取)
- improvements: 改进建议 (5-10 条, 自动基于低分维度生成)
- similar_cases_comparison: 类似案件对比 (复用 W11 类案界面语言规范)
- narrative: narrative 文本 (强制 language_guard, 禁用"必胜/必败/一定")
- disclaimer: 强制免责声明

**关键设计**:
- 5 维度评分自动 clamp 到 [0, 1] (测试 `test_five_dimension_scores_clamped` 验证)
- 改进建议自动生成 (基于低分维度 + 5 条通用建议)
- 类似案件对比模板 (高/中/低分 3 段式)
- narrative 强制 language_guard (禁用词替换为合规表述, 测试 `test_debrief_report_no_bypass_words` 验证)

## 3. 5 状态机 (复用 W12 doc_workflow 模式)

**API 端点**: `POST /api/skill4/state-transition`

**状态机**:
```
draft → ai_reviewed → lawyer_reviewed → settled → archived
        ↑                                ↓
        └─────── (back to review) ───────┘
```

**转移规则** (复用 W12 829d25c doc_workflow):

| From | To | 触发条件 |
|------|-----|---------|
| draft | ai_reviewed | AI 策略生成完成 (POST /strategies 自动转移) |
| ai_reviewed | lawyer_reviewed | 律师评审通过 |
| ai_reviewed | draft | 重新生成策略 |
| lawyer_reviewed | settled | 达成和解 |
| lawyer_reviewed | ai_reviewed | 重新 AI 评审 |
| settled | archived | 归档 (终态) |
| settled | lawyer_reviewed | 重新协商 |
| archived | (none) | 终态, 不可转移 |

**测试覆盖** (`TestNegotiationStateMachine`):
- `test_state_machine_initial_state`: 初始状态 = draft
- `test_state_transitions_valid`: 合法转移 (draft → ai_reviewed → lawyer_reviewed → settled → archived)
- `test_state_invalid_transition_blocked`: 非法转移 (draft 直接跳 settled 必须抛 ValueError)
- `test_state_machine_terminal_states`: 终态 (archived) 不可转移
