## 1. 产品定位

### 1.1 Skill 5 自动谈判是什么

> **Skill 5 自动谈判**: AI 代表律师进行初步谈判, 律师审核确认.
>
> - **Skill 4 (辅助)**: AI 提供谈判策略建议, 律师自己做谈判
> - **Skill 5 (自动)**: AI 自动进行初步谈判, 律师审核确认结果
>
> **核心差异**: Skill 4 是"副驾驶", Skill 5 是"自动驾驶 (L3 级)".

### 1.2 目标用户

| 用户类型 | 使用场景 | 频率 |
|---------|---------|------|
| 诉讼律师 | 标的 < 50 万的简单案件初步谈判 | 每周 2-5 次 |
| 非诉律师 | 合同条款初步谈判 | 每周 1-3 次 |
| 法律助理 | 简单催收/和解谈判 | 每天 |

### 1.3 核心价值

| 价值 | 说明 |
|------|------|
| **效率提升** | 律师从"每次谈判 2 小时" → "审核谈判结果 15 分钟" |
| **成本控制** | 简单案件可由 AI 谈判, 律师只需审核 |
| **一致性** | AI 谈判策略基于历史数据和最佳实践, 更一致 |
| **可扩展性** | 1 个律师可同时处理 10+ 场 AI 谈判 |

## 2. 功能范围

### 2.1 Skill 5 核心模块

| 模块 | 功能 | 优先级 |
|------|------|--------|
| **谈判目标设定** | 律师设定谈判目标 (最低接受价/理想价/底线) | P0 |
| **AI 谈判执行** | AI 自动进行初步谈判 (邮件/电话/在线) | P0 |
| **律师审核确认** | 律师审核 AI 谈判结果, 确认/修改 | P0 |
| **谈判策略学习** | 从律师审核中学习, 优化后续谈判策略 | P1 |
| **多轮谈判支持** | 支持多轮谈判 (初始报价 → 反报价 → 最终协议) | P1 |
| **谈判记录归档** | 自动记录谈判过程, 生成谈判报告 | P2 |

## 3. 技术架构

### 3.1 核心技术栈

| 技术 | 用途 |
|------|------|
| **Qwen2.5-72B** | 谈判策略生成 + AI 谈判执行 |
| **RAG** | 历史谈判数据检索 + 最佳实践参考 |
| **Fine-tuning** | 律师审核数据微调 (W34+) |
| **LangChain** | 谈判流程编排 |
| **SQLite/PG** | 谈判记录存储 |

### 3.2 系统架构图

```
[律师设定目标] → [谈判目标设定模块] → [AI 谈判执行模块] → [律师审核确认] → [谈判结果]
                                              ↓
                                    [谈判策略学习模块]
                                              ↓
                                   [Fine-tuning 数据池]
```

### 3.3 API 设计

| 端点 | Method | 功能 |
|------|--------|------|
| `/api/skill5/negotiations` | POST | 创建谈判 (设定目标) |
| `/api/skill5/negotiations/{id}/execute` | POST | 执行 AI 谈判 |
| `/api/skill5/negotiations/{id}/review` | PUT | 律师审核确认 |
| `/api/skill5/negotiations/{id}/feedback` | POST | 律师反馈 (用于学习) |
| `/api/skill5/negotiations/{id}/history` | GET | 谈判历史记录 |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| AI 谈判结果不准确 | 高 | 律师审核确认机制 + 策略学习优化 |
| 律师不接受 AI 谈判 | 中 | 渐进式上线 (先简单案件, 后复杂案件) |
| 法律合规风险 | 高 | 严守"AI 辅助, 不替代律师"边界 |
| 数据隐私风险 | 高 | 谈判数据本地存储, 不上传云端 |
