  - 综合评分 ≥ 4.0
  - D1 (致命/重大准确率) ≥ 85% (折算: D1 评分 ≥ 4.25)
  - D4 (中立性) 0 违规 (D4 评分 = 5)

## 2. 评分维度 1: 三级风险识别准确率 (30% 权重)

### 2.1 评分方法

| 子项 | 权重 | 评分依据 |
|---|---|---|
| 致命风险识别 | 10% | 5 合同 4 个 fatal 全检出 + 无误报 |
| 重大风险识别 | 10% | 5 合同 4 个 major 全检出 + 无误报 |
| 建议风险识别 | 10% | 5 合同 14 个 advisory 全覆盖 + 无过度 |

### 2.2 致命风险识别 (10% 权重)

**评分公式**:
```
致命评分 = 5 × (1 - 漏检数/4) - 误报数 × 0.5
```

**详细评分标准**:

| 评分 | 标准 |
|---|---|
| 5 | 4 个 fatal 全检出, 0 误报, 风险类型识别正确 |
| 4 | 4 个 fatal 全检出, ≤ 1 误报 (类型识别允许 1 处偏差) |
| 3 | 漏 1 个 fatal, 0 误报 (可接受但需补) |
| 2 | 漏 1 个 fatal + 1 误报, 或漏 2 个 fatal |
| 1 | 漏 ≥ 2 个 fatal, 或 fatal 误报 ≥ 2 |

**fatal 类型清单** (PRD § 3.12.2):
- 违约金过高 (司法保护上限外)
- 显失公平 (违反民法典第六条公平原则)
- 违法条款 (违反法律强制性规定)
- 重大遗漏 (缺少必备条款, 影响合同效力)
- 管辖连接点异常 (违反专属管辖)
- 解除权严重失衡 (单方任意解除)

### 2.3 重大风险识别 (10% 权重)

**评分公式**:
```
重大评分 = 5 × (1 - 漏检数/4) - 误报数 × 0.5
```

**详细评分标准**: 同 §2.2 致命风险 (4 分制阈值平移)

**major 类型清单** (PRD § 3.12.2):
- 隐含义务 (条款暗含一方义务但未明确)
- 争议管辖不利 (约定单方住所地管辖)
- 期限异常 (期限超出合理范围)
- 举证困难 (条款导致举证责任分配不利)
- 金额异常 (金额表述不明确 / 大小写不符)
- 解除权失衡 (解除条件不对等)

### 2.4 建议风险识别 (10% 权重)

**评分公式**:
```
建议评分 = 5 × min(覆盖率, 1.0) - 过度率 × 2
```

| 评分 | 标准 |
|---|---|
| 5 | 14 个 advisory 候选覆盖 ≥ 90%, 0 过度 |
| 4 | 覆盖 ≥ 75%, ≤ 1 过度 |
| 3 | 覆盖 ≥ 60%, ≤ 2 过度 |
| 2 | 覆盖 ≥ 40%, 或过度 ≥ 3 |
| 1 | 覆盖 < 40%, 或过度 ≥ 5 |

**advisory 类型清单** (PRD § 3.12.2):
- 表述模糊 (条款用语不精确)
- 可优化 (可结合行业惯例改进)
- 条款缺失非必备项 (建议补充)

### 2.5 三级风险综合评分

```
D1 = (致命评分 × 0.4) + (重大评分 × 0.4) + (建议评分 × 0.2)
D1 ≥ 4.25 = 致命/重大准确率 ≥ 85% (通过门槛)
```

## 3. 评分维度 2: 修改建议实用性 (25% 权重)

### 3.1 评分方法

| 子项 | 权重 | 评分依据 |
|---|---|---|
| 修改建议质量 | 15% | 可执行 + 法条准确 + 行业适配 + 表述清晰 |
| 修改建议覆盖度 | 10% | fatal/major 100% 覆盖 + 模板可替换 |

### 3.2 修改建议质量 (15% 权重)

| 评分 | 标准 |
|---|---|
| 5 | 可直接采用, 法条引用 100% 准确, 行业惯例契合, 表述专业 |
| 4 | 稍作修改可用, 法条 ≥ 90% 准确, 行业惯例基本契合 |
| 3 | 律师需改写 30-50% 内容, 法条 80% 准确, 偶尔脱离行业 |
| 2 | 律师需改写 > 50%, 法条错误 ≥ 2 处, 行业适配差 |
| 1 | 不可用, 律师完全弃用, 法条错误 ≥ 3 处 |

**检查清单**:
- [ ] 修改建议是否给出具体表述 (vs 抽象建议)
- [ ] 修改建议是否引用法条 (民法典 / 民诉法 / 劳动法 等)
- [ ] 修改建议是否给出具体数值范围 (如"按 LPR × 1.5 倍")
- [ ] 修改建议是否考虑行业惯例 (如 IT 服务 vs 房屋租赁 违约金惯例不同)
- [ ] 修改建议是否含 modified_clause_template (一键替换模板)

### 3.3 修改建议覆盖度 (10% 权重)

| 评分 | 标准 |
|---|---|
| 5 | fatal 100% 覆盖, major 100% 覆盖, modified_clause_template ≥ 80% fatal |
| 4 | fatal 100% 覆盖, major 100% 覆盖, template 60-80% |
| 3 | fatal 100% 覆盖, major 漏 1-2 个, template < 60% |
| 2 | fatal 漏 ≥ 1 个 (P0 缺陷) |
| 1 | fatal 漏 ≥ 2 个 (一票否决) |

### 3.4 修改建议实用性综合

```
D2 = (质量 × 0.6) + (覆盖度 × 0.4)
D2 ≥ 4.0 = 实用性 ≥ 70% 律师认可 (软门槛)
```

## 4. 评分维度 3: 谈判策略可执行性 (20% 权重)

### 4.1 评分方法

| 子项 | 权重 |
|---|---|
| priority_clauses 排序 | 4% |
| leverage_points 描述具体性 | 4% |
| trade_off 合理性 | 4% |
| walk_away_signals 红线识别 | 4% |
| stance_specific_advice 立场感知 | 4% |

### 4.2 评分细则

| 评分 | 标准 |
|---|---|
| 5 | 5 子项全部 5 分, 律师可直接采用谈判策略 |
| 4 | 4 子项 4 分 + 1 子项 3 分, 律师稍作调整可用 |
| 3 | 3 子项 4 分 + 2 子项 3 分, 律师需补充行业经验 |
| 2 | ≥ 2 子项 2 分, 策略不切实际 |
| 1 | ≥ 2 子项 1 分, 律师完全弃用 |

### 4.3 子项检查清单

**priority_clauses 排序**:
- [ ] 是否按 fatal > major > advisory 排序
- [ ] 是否考虑立场 (甲方 vs 乙方 优先级不同)
- [ ] 是否给出排序理由 (不只是列表)

**leverage_points 描述具体性**:
- [ ] 是否给出可操作的谈判筹码 (vs 抽象"可以谈")
- [ ] 筹码是否引用行业惯例 / 司法实践
- [ ] 筹码是否分短期 / 长期

**trade_off 合理性**:
- [ ] 让步方向是否行业可行 (vs 漫天要价)
- [ ] 是否给出具体让步幅度
- [ ] 是否考虑双方底线

**walk_away_signals 红线识别**:
- [ ] 是否识别了不能谈判的致命条款
- [ ] 红线描述是否清晰 (vs 模糊"有风险")
- [ ] 是否给出红线触发后的备选方案

**stance_specific_advice 立场感知**:
- [ ] 4 立场 (甲方/乙方/丙方/审查方) 差异化建议质量
- [ ] 立场切换时建议是否自动调整
- [ ] 是否考虑立场组合 (如联合体 / 多方合同)

### 4.4 谈判策略可执行性综合

```
D3 = (priority + leverage + trade_off + walk_away + stance) / 5
D3 ≥ 3.25 = 谈判策略 ≥ 65% 律师认可 (软门槛)
```

## 5. 评分维度 4: LLM 输出中立性 (15% 权重, 一票否决)

### 5.1 评分方法 (PRD § 5.7 硬约束)

**禁用词清单** (来自 `language_policy.md`):
- "合同必败" / "合同必胜"
- "必将败诉" / "必将胜诉"
- "该合同违法" / "该合同无效"
- "100% 站不住" / "稳赢"
- 任何确定性预测

**必须含**:
- "可能构成" / "存在风险" / "建议进一步核实"
- 法条引用 (条款编号)
- disclaimer 强制显示
- 来源标注 (模板 / 法条 / 类案)

### 5.2 评分细则 (一票否决)

| 评分 | 标准 |
|---|---|
| 5 | 0 违规, 0 不确定, 全部用"可能/建议" 表述, disclaimer 100% 显示 |
| 4 | 0 违规, 1 处表述不够中立 (如"通常无效" 应改"可能无效") |
| 3 | 0 违规, 2 处表述不够中立 |
| 2 | 1 处违规 (触发 P0 改进) |
| 1 | ≥ 2 处违规 (一票否决, 综合 = 0) |

### 5.3 中立性检查清单

- [ ] Skill 输出 narrative 全部通过 language_guard.py 正则检查
- [ ] fatal 风险描述用"可能构成 X" 而非"该条款违法"
- [ ] major 风险描述用"存在 X 风险" 而非"该条款无效"
- [ ] advisory 风险描述用"建议优化" 而非"该条款错误"
- [ ] 谈判策略不含"应该接受/应该拒绝" 等指令性语言
- [ ] 整体叙事不预测合同结果
- [ ] disclaimer 在所有输出末尾强制显示

### 5.4 中立性综合

```
D4 = 5 - 违规数 × 2 - 不中立表述数 × 0.5
D4 = 5 = 0 违规 (通过门槛, 硬)
```

## 6. 评分维度 5: 整体可用性 (10% 权重)

### 6.1 评分方法

| 子项 | 权重 |
|---|---|
| UI 易用性 | 3% |
| 风险高亮清晰度 | 2% |
| 红黄绿灯整体判断 | 2% |
| 加载速度 | 1% |
| 导出格式 | 1% |
| 其他 (UX/性能) | 1% |

### 6.2 评分细则

| 评分 | 标准 |
|---|---|
| 5 | UI 流畅, 高亮清晰, 红绿灯准确, 加载 < 1s, 导出格式齐全 |
| 4 | UI 偶有卡顿, 高亮清晰, 红绿灯偶有偏差, 加载 < 2s, 导出 3 种格式 |
| 3 | UI 一般, 高亮可辨, 红绿灯基本准确, 加载 2-3s, 导出 2 种格式 |
| 2 | UI 不流畅, 高亮模糊, 红绿灯偏差大, 加载 3-5s, 导出 1 种格式 |
| 1 | UI 难用, 高亮不工作, 红绿灯错乱, 加载 > 5s, 无导出 |

### 6.3 UI 子项检查清单

**UI 易用性**:
- [ ] 上传合同 (PDF / Word / 图片 / 粘贴文本) → 启动审查 流程顺畅
- [ ] 风险高亮 + 修改建议 + 谈判策略 三栏切换不卡顿
- [ ] 立场切换 (甲方/乙方/丙方/审查方) 自动重新审查

**风险高亮清晰度**:
- [ ] 致命 = bg-red-100 + 红边框 + 警告图标
- [ ] 重大 = bg-amber-100 + 黄边框
- [ ] 建议 = bg-blue-50 + 蓝边框
- [ ] 悬浮提示含风险描述 + 法条 + 修改建议入口

**红黄绿灯整体判断**:
- [ ] 红 = 存在 fatal (跟律师独立判断一致率 ≥ 90%)
- [ ] 黄 = 存在 major 无 fatal (一致率 ≥ 85%)
- [ ] 绿 = 仅 advisory (一致率 ≥ 80%)
- [ ] 灰 = 无审查 / 数据不足

**加载速度** (manifest.json: p95_latency_ms_target = 2000):
- [ ] 5 合同 LLM 审查 P95 < 2s
- [ ] LanceDB 检索 P95 < 200ms (W4 目标)

**导出格式**:
- [ ] Word (.docx) — 含风险高亮 + 修改建议 + 谈判策略
- [ ] PDF — 同 Word, 但不可编辑
- [ ] Markdown — 纯文本, 方便二次编辑

### 6.4 整体可用性综合

```
D5 = 6 子项平均
D5 ≥ 4.0 = 整体可用 (通过门槛)
```

## 7. 综合评分与结论

### 7.1 综合评分公式

```
综合 = 0.30 × D1 + 0.25 × D2 + 0.20 × D3 + 0.15 × D4 + 0.10 × D5
```

### 7.2 结论判定

| 综合 | 结论 | 后续动作 |
|---|---|---|
| ≥ 4.0 + D1 ≥ 4.25 + D4 = 5 | **通过** | Skill 商用, 律师愿意使用 |
| ≥ 4.0 + D1 ≥ 4.25 + D4 = 5 + 软门槛触发 | **有条件通过** | 补 P0 改进, W7 复评 |
| < 4.0 或 D1 < 4.25 或 D4 < 5 或硬门槛触发 | **不通过** | 重新设计, W8+ 复评 |

### 7.3 软门槛处理

| 软门槛 | 触发条件 | 后续动作 |
|---|---|---|
| 实用性 ≥ 70% | D2 ≥ 4.0 | 持续监控, 季度复评 |
| 实用性 < 70% | D2 < 4.0 | P0 改进: 修改建议质量 + 覆盖度 |
| 谈判策略 ≥ 65% | D3 ≥ 3.25 | 持续监控, 季度复评 |
| 谈判策略 < 65% | D3 < 3.25 | P1 改进: 立场感知 + 筹码描述 |
| 整体可用 < 4.0 | D5 < 4.0 | P1 改进: UI 优化 + 性能调优 |
