# LexPrime 系统架构文档

## 系统架构图描述

LexPrime 采用分层架构设计，从前端到后端分为展示层、应用层、服务层、数据层四个层次，各层职责清晰、松耦合。

## 模块划分

### 1. API 模块

#### 1.1 主路由 (`api/main.py`)

- 健康检查端点
- 前端日志接收
- 判例检索端点
- 法规查询端点
- 企业查询端点
- 全文搜索端点
- 律所管理端点

#### 1.2 合同审查路由 (`api/contract_review_router.py`)

- 合同上传审查
- 审查结果查询
- 谈判策略生成
- 报告导出

#### 1.3 AI 路由 (`api/ai_router.py`)

- AI 对话接口
- 案件摘要生成
- 文书润色
- 智能填空

#### 1.4 Marketplace 路由 (`api/marketplace_router.py`)

- 律师管理
- 协同办案
- 转介绍系统
- 跨境文件服务

#### 1.5 日程路由 (`api/schedule_router.py`)

- 日程 CRUD
- 时间冲突检查
- 今日日程

#### 1.6 客户路由 (`api/client_router.py`)

- 客户管理
- 利益冲突检查
- 客户统计

### 2. 核心业务模块

#### 2.1 数据库模块 (`core/database.py`)

- 数据库连接管理
- 异步会话创建
- 引擎初始化

#### 2.2 Elasticsearch 模块 (`core/es_client.py`)

- ES 连接管理
- 索引操作
- 搜索查询

#### 2.3 Neo4j 模块 (`core/neo4j_client.py`)

- Neo4j 连接管理
- 图查询
- 知识图谱操作

#### 2.4 Marketplace 引擎 (`core/marketplace_engine.py`)

- 律师匹配算法（5维度评分）

#### 2.5 合同审查引擎 (`core/contract_review_engine.py`)

- 规则引擎
- 风险评估

### 3. 模型模块 (`models/`)

## 数据流说明

### 1. 判例检索流程

```
用户请求 → API Router → ES Client → Elasticsearch → 返回结果
                        ↓
                  Database → PostgreSQL (补充详情)
```

1. 用户发起检索请求
2. API 路由接收请求
3. ES Client 执行全文搜索
4. 返回搜索结果（含 doc_id）
5. 根据 doc_id 查询 PostgreSQL 获取完整详情

### 2. 合同审查流程

```
上传合同 → API Router → Contract Review Engine → AI Service (LLM)
                                                      ↓
                                                规则引擎评估
                                                      ↓
                                                生成审查报告
                                                      ↓
                                                存储到 PostgreSQL
                                                      ↓
                                                返回审查结果
```

1. 用户上传合同文本
2. API 路由接收请求
3. 合同审查引擎处理
4. 调用 AI 服务分析合同
5. 规则引擎进行风险评估
6. 生成审查报告并存储
7. 返回审查结果

### 3. 律师匹配流程

```
案件需求 → API Router → Marketplace Engine → 计算匹配分数
                                                  ↓
                                            查询律师数据库
                                                  ↓
                                            排序推荐
                                                  ↓
                                            返回推荐列表
```

1. 用户提交案件需求
2. API 路由接收请求
3. Marketplace 引擎计算匹配分数（5维度）
   - 专业领域匹配
   - 经验年限
   - 地域匹配
   - 可用性
   - 评分
4. 查询律师数据库
5. 按匹配分数排序
6. 返回推荐列表

### 4. AI 对话流程

```
用户提问 → API Router → AI Service → OpenAI/Claude API
                                        ↓
                                  返回回答
                                        ↓
                                  添加免责声明
                                        ↓
                                  返回给用户
```

1. 用户输入问题
2. API 路由接收请求
3. AI Service 调用外部 LLM API
4. 接收 AI 回答
5. 添加法律免责声明
6. 返回给用户

### 5. 日程管理流程

```
创建日程 → API Router → 冲突检测 → 存储到 PostgreSQL → 返回成功
              ↓
        Redis (缓存今日日程)
```

1. 用户创建日程
2. API 路由接收请求
3. 执行时间冲突检测
4. 存储到 PostgreSQL
5. 更新 Redis 缓存
6. 返回成功响应

### 6. 客户管理流程

```
添加客户 → API Router → 利益冲突检查 → 存储到 PostgreSQL → 返回成功
                           ↓
                     Neo4j (客户关系图谱)
```

1. 用户添加客户
2. API 路由接收请求
3. 执行利益冲突检查（查询 Neo4j）
4. 存储到 PostgreSQL
5. 更新 Neo4j 客户关系图谱
6. 返回成功响应

## 关键设计决策

### 1. 数据库选择

- **PostgreSQL**：作为主数据库，支持复杂查询、JSON 字段、全文搜索等特性
- **Elasticsearch**：专门用于全文搜索，提供高效的检索能力
- **Neo4j**：用于知识图谱和关系分析，支持利益冲突检查

### 2. 架构风格

- **分层架构**：清晰的职责分离，便于维护和扩展
- **异步设计**：使用 FastAPI + asyncio，提高并发处理能力
- **依赖注入**：通过 FastAPI 的 Depends 实现依赖管理

### 3. 数据缓存

- Redis 缓存热点数据（今日日程、常用判例等）
- 减少数据库查询压力
- 提高响应速度

### 4. 日志和监控

- 结构化日志记录
- 健康检查端点
- 前端性能日志收集

### 5. 安全性

- JWT Bearer Token 认证
- CORS 中间件
- 请求参数校验
- 异常处理
