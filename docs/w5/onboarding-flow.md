## 1. 设计目标

### 1.1 一句话定位

> **5 步引导让律师 5 分钟内体验 LexPrime 核心价值 (上传案件 → 类案检索 → 合同审查 → 邀请同行 → 关注公众号), 而不是空看工作台不知道干嘛。**

### 1.2 关键原则

| 原则 | 体现 |
|------|------|
| **不强制** | 每一步都有「跳过」按钮, 律师可随时退出 |
| **价值先于功能** | 引导的不是「按钮在哪」, 而是「这功能怎么帮你省时间」 |
| **5 分钟上限** | 单步操作 ≤ 60s, 5 步总时长 ≤ 5 分钟 |
| **可回访** | 任何时候点工作台右上角的「?」都能重看引导 |
| **完成有奖** | 完成 3 步及以上奖励「优先审核」标识 (后续可叠加优惠券) |

### 1.3 触发场景

| 触发点 | 页面 | 模式 |
|--------|------|------|
| 注册成功 | `/welcome` 欢迎页 | 软引导 (大按钮 + 跳过) |
| 首次进入工作台 | `workstation.html` 顶部 | 浮层引导 (Tooltip 链) |
| 手动回访 | 工作台右上角「?」→ 重看 | 浮层引导 |

## 2. 5 步引导详细设计

### 2.1 步骤总览

| # | 步骤名 | 目标动作 | 价值主张 | 时长 |
|---|--------|----------|----------|------|
| 1 | 上传首个案件 | 创建案件 + 上传 1 份材料 | "5 秒搞定一个案件, AI 自动提取 15 字段" | 60s |
| 2 | 跑类案检索 | 在案件详情点类案检索按钮 | "类案检索从 30 分钟变 30 秒" | 45s |
| 3 | 跑合同审查 | 上传 1 份合同 → AI 跑风险点 | "5 分钟看完整份合同的高风险条款" | 90s |
| 4 | 邀请同行 | 复制邀请链接 / 微信扫码 | "邀请同行, 各得 30 天延长" | 30s |
| 5 | 关注公众号 | 扫码关注公众号 | "关键功能更新 + 律师社群入口" | 20s |

> **总计**: 5 分钟上限, 律师可跳过任意步骤, 完成 ≥3 步即视为"激活"

### 2.2 步骤 1: 上传首个案件

**触发**: 注册成功 → `/welcome` 欢迎页 → 点击「开始 5 步引导」

**UI 设计** (全屏引导页, 不可关闭背景):
```
+------------------------------------------------+
|  [1/5] ●○○○○                  [跳过引导 X]    |
|                                                |
|  🎯 上传您的首个案件                            |
|                                                |
|  律师 80% 时间在案牍. 5 秒搞定一个案件,        |
|  AI 自动提取 15 个字段 (原告/被告/案由/标的...).|
|                                                |
|  [图示: 上传案件 → AI 提取 → 列表显示]          |
|                                                |
|  +-- 立即上传 -----------------+              |
|  | 拖拽 PDF/Word/图片 到这里   |              |
|  | 或 [选择文件]              |              |
|  +-----------------------------+              |
|                                                |
|  [ 我已上传, 下一步 → ]   [跳过本步]            |
|                                                |
|  💡 提示: 您可以先建空案件, 稍后再上传材料      |
+------------------------------------------------+
```

**关键文案**:
- 标题: "上传您的首个案件"
- 副标题: "5 秒搞定一个案件, AI 自动提取 15 字段"
- 跳过文案: "我先看看工作台" (不出现在第 1 步, 避免一上来就放弃)

**后端埋点**:
- `onboarding_step_1_start` - 步骤开始
- `onboarding_step_1_file_upload` - 文件上传
- `onboarding_step_1_complete` - 步骤完成 (创建案件成功)
- `onboarding_step_1_skip` - 跳过

### 2.3 步骤 2: 跑类案检索

**前置**: 完成步骤 1 (有案件)

**UI 设计** (跳转至案件详情页, 高亮类案检索按钮):
```
+------------------------------------------------+
|  [2/5] ●●○○○                  [跳过引导 X]    |
|                                                |
|  🔍 跑类案检索                                  |
|                                                |
|  传统检索: 30 分钟 (裁判文书网 + 关键词组合)    |
|  LexPrime: 30 秒 (AI 理解案件 + 全库语义检索)   |
|                                                |
|  +----------------------------+               |
|  | 案件: 张三诉李四买卖合同    |               |
|  | [类案检索] ←  ←  ←  ← 高亮 |               |
|  +----------------------------+               |
|                                                |
|  检索结果预览:                                  |
|  ✅ 找到 23 个相关类案                          |
|  ✅ 按法院层级 / 案由 / 标的额 自动分组           |
|                                                |
|  [ 已体验, 下一步 → ]   [跳过本步]              |
+------------------------------------------------+
```

**关键设计**:
- 不强制用户真的跑检索, 但「已体验」按钮只在用户**真的点过**类案检索按钮后才亮起
- 否则按钮置灰, 文案提示: "请先点 [类案检索] 按钮体验"
- 这样保证激活质量, 不是「点下一步就算体验」

## 3. 进度条 + 跳过策略

### 3.1 顶部进度条

- 5 个圆点 ●○○○○, 已完成实心 brand 色, 未完成 fg-disabled
- 步骤切换时进度条平滑过渡 (200ms ease-out)
- 进度条点击允许跳转 (W6 实现, W5 仅展示)

### 3.2 跳过策略

| 跳过类型 | 触发 | 后续行为 |
|----------|------|----------|
| **跳过单步** | 点「跳过本步」 | 该步骤标为跳过, 进度条对应圆点变 urgent-tint 半透明 |
| **跳过引导** | 顶部 [跳过引导 X] | 弹出二次确认 "确定跳过引导? 您可以随时点右上角「?」重看" |
| **完成 3 步** | 自动提示 | 触发完成页, 给"优先客服"标识 |
| **完成 5 步** | 自动提示 | 触发完成页 + 创始体验官申请 CTA |

### 3.3 不强制原则的边界

- **不强制**: 不弹窗拦截律师, 不锁工作台, 不要求完成才能用核心功能
- **软激励**: 完成 5 步 = 优先客服 + 创始体验官资格; 跳过 = 不给激励, 但功能照常用
- **可回访**: 工作台右上角「?」图标永远存在, 任何时候点开重看

## 5. 激活指标 (PM 关键设计)

### 5.1 定义激活

律师完成 **≥3 步** 视为"激活用户" (Activated User)

| 激活级别 | 完成步骤数 | 标识 |
|----------|-----------|------|
| **未激活** | 0-2 步 | 无标识 |
| **已激活** | 3-4 步 | 工作台顶部「优先客服」徽章 |
| **完美激活** | 5 步全完成 | 上述 + 创始体验官申请入口 |

### 5.2 激活转化漏斗 (跟 trial funnel 联动)

```
[注册成功] 100%
    ↓
[进入 /welcome] 95%
    ↓
[点击「开始引导」] 70%
    ↓
[完成 1 步] 60%
    ↓
[完成 3 步 = 激活] 50%   ← PM 目标 ≥ 50%
    ↓
[完成 5 步 = 完美激活] 30%
```

### 5.3 激活 vs 留存的关联

PM 假设: **激活用户的 30 天留存率 ≥ 80%**, 远高于未激活用户的 30%.

**W6 验证**: 用 Track D 的 cohort 分析验证, W12 出激活-留存关联报告.

## 6. 跟 trial / paywall 的联动

### 6.1 跟 trial 注册流程的关系

```
[注册成功] → [trial.start API] → [trial_id 生成] → [Onboarding 触发]
                                              ↓
                                     [trial.onboarding_complete 事件]
                                              ↓
                                     [trial_days_used 计数开始]
```

### 6.2 跟付费墙的关系

Onboarding 完成后, trial 状态从「active + 未激活」变为「active + 已激活」, 后端记录激活时间:
- Day 23 提醒时, 优先给已激活律师发 (更高转化概率)
- 已激活律师的「付费墙」触发时, 文案更柔和 (「升级解锁高级功能, 您已熟悉的体验不要停」)
- 未激活律师的付费墙文案: 「升级解锁高级功能, 帮您从 0 到 1 体验 LexPrime」
