# Track B: OCR 闭环 (PaddleOCR + 证据分类)

> 来源: PRD § 9.2 Phase 4 计划 · 12 周 Phase 4 第 5-7 周
> 负责人: 全栈 + AI · 优先级: P0 · 工时: 3 周

---

## 1. 目标

律师可扫描或上传证据材料, 系统自动 OCR 识别 + 分类 + 目录生成。

## 2. 范围 (In Scope)

- PaddleOCR 接入 (本地)
- 证据分类 (合同 / 票据 / 聊天记录 / 身份证 / 判决书 等)
- 自动证据目录生成
- 多模态: 图片 / PDF / 扫描件
- 失败重试 + 人工标注兜底

## 3. 不在范围 (Out of Scope)

- 复杂扫描件云端 OCR (Phase 4.5)
- OCR 模型自训练 (用预训练模型)

## 4. 任务分解

- W5: PaddleOCR 部署 + 基础接入 + PDF/图片支持
- W6: 证据分类模型 (微调或 prompt) + 自动目录
- W7: 失败重试 + 人工标注 + 批量上传 + 性能优化

## 5. 验收标准 (Acceptance Criteria)

- [ ] 律师可上传 PDF / 图片, 5 秒内 OCR 完成
- [ ] 分类准确率 ≥ 85% (律师可手动调整)
- [ ] 证据目录自动生成 (按主体资格 / 程序性 / 实体性排序)
- [ ] 失败可重试, 人工标注回流
- [ ] 单批次 100 份证据 < 5 分钟

## 6. 依赖

**前置 Track**: A (Auth)
**技术依赖**: PaddleOCR 2.7+ / FastAPI 异步 / 对象存储 (MinIO 或本地)
**资源依赖**: GPU 服务器 (OCR 加速, 可选)

## 7. 风险

- OCR 准确率不足 → 人工标注兜底 + 主动学习
- 扫描件质量差 → 图像预处理 (去噪 / 增强)
- 大文件上传慢 → 分片上传 + 断点续传
