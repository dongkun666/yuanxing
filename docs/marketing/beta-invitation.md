```

[Day 7 留存] 60%    激活律师的 7 日留存
    ↓
[Day 30 转化付费] 30%+  ← PRD 目标
```

## 5. 邀请函视觉规范 (跟 W1 设计系统一致)

### 5.1 配色

| 元素 | 颜色 | 用途 |
|------|------|------|
| 主色 | `#165DFF` (brand) | CTA 按钮 / 链接 / Logo |
| AI 紫 | `#6C5CE7` (ai) | "AI 辅助" 标识 / 角标 |
| 微信绿 | `#07C160` (wechat) | 微信二维码 / 微信 CTA |
| 紧急橙 | `#FA8C16` (urgent) | 限量 / 倒计时 / 紧迫感 |
| 成功绿 | `#00B42A` (success) | 福利勾选 / 完成状态 |

### 5.2 文案规范

- **不用**: "立即购买" / "限时折扣" / "错过不再有" / "AI 自动办案" / "替代律师"
- **用**: "免费试用" / "30 天" / "无信用卡" / "AI 辅助" / "数据本地化"
- **称呼**: 一律用 "您" 不用 "你" (体现专业感)
- **律所/公司**: 首次出现用全称, 后续简称

### 5.3 图片规范

- **必须**: 真实产品截图 (workstation.html 主屏 + 类案 + 合同审查 3 张)
- **禁止**: 营销模板图 / 库存图 / AI 生成的"假截图"
- **格式**: PNG 高清, 宽度 1200px, 大小 < 500KB
- **命名**: `lexprime-workstation.png` / `lexprime-skill1-case.png` / `lexprime-skill2-contract.png`

### 5.4 二维码

- **公测链接**: 微信群发版配 1 张产品二维码 (指向 https://yuanxing.app/r/[专属链接])
- **创始人微信**: 1 对 1 / 邮件版配 1 张微信二维码 (建议新开工作号)
- **公众号**: W6 公众号上线后, onboarding step 5 替换真实二维码

## 6. 风险与应对 (BD + PM)

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 律师收到邀请不点 (邮箱被忽略) | 高 | 高 | 微信 + 邮件双发 + 朋友圈持续预热 |
| 律师点链接不注册 (跳转流失) | 中 | 高 | 注册页加 1 屏产品截图预览, 让律师注册前看到产品 |
| 律师注册不激活 (Onboarding 跳过) | 高 | 高 | Day 1 / Day 3 邮件提醒 + 1v1 微信辅助 |
| 律师试用到期不付费 | 中 | 高 | Day 23/29/31 三段提醒 (见 trial-registration-flow.md §4.3) |
| 律师拉黑朋友圈 (觉得是广告) | 低 | 中 | 控制频率 (每周 ≤ 2 条朋友圈), 不刷屏 |
| 律师提负面反馈 (跟竞品比) | 中 | 中 | 接受负面, 列入 PRD §15 待办, 不辩解 |
| 律师要求退款 (试用期内不可能, 付费后) | 低 | 中 | W6 写退款政策, 30 天内可全额退 |

## 9. 整理人备注 (PM)

- 公测邀请函是 **总指挥**亲自发的, 不是系统自动 — 律师对"机器人邀请"敏感, 1v1 微信必须人工
- 邀请函模板的核心是 **3 个不**: 不强制付费 / 不刷屏 / 不夸张. 律师群体对营销文案警惕性高
- 配套 `onboarding-flow.md` 的 5 步引导, 是公测注册后的承接 — 邀请函只是入口, 真正留住律师是 onboarding
- W3 末根据访谈 #2 的反馈调整邮件版 (中小所主任最在意"成本 + 团队协同")
- W7 末 BD 出转化漏斗实际数据, 调优公测策略

> **PM 责任**: W5 文档交付, W6 跟 BD 联动审核 5 位律师反馈, W7 末看实际转化, W8 出公测报告.
