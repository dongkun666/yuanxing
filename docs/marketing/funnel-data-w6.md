# 首月转化漏斗数据 (Funnel Data W6)

> **版本**: v0.1 · 2026-06-29
> **Track**: D (公测预热 + 漏斗跟踪)
> **Week**: W6 Day 3-5 (公测期 7/26 - 8/9)
> **目标**: 100 试用 / 50 活跃 / 5 付费 (首月 W6 末 - W8 末)
> **配套**: `tracking-events.md` (埋点规范) · `dashboard-w6.md` (日看板) · `prd/10-success-metrics.md` § 11.2.1 (主漏斗)
>
> **使用说明**: 本文档是 **公测期 5 步漏斗的数据汇总表**, 每日 BD 更新, Mavis 跑数据后回填.
> 漏斗定义: 访问 → 试用 → 7 日活跃 → 30 日活跃 → 付费 (5 步, 严格按时间窗口).
> 数据来源: 邀请码系统 (status: unused/redeemed/active) + 埋点事件 (5 个 event 字段) + 支付系统 (Stripe 接入后).

## 1. 漏斗总览 (5 步)

### 1.1 5 步漏斗定义

| 步骤 | 事件 | 触发条件 | 时间窗口 | 数据源 |
|------|------|----------|----------|--------|
| **1. 访问** | `funnel_step1_visit` | 用户打开 landing (5 大模块任一 PV) | 7/26 - 8/9 | 埋点 |
| **2. 试用** | `funnel_step2_trial` | 用户完成 trial_register_submit (5 步 7 步漏斗的 step 3) | 注册成功 7/26 - 8/9 | 邀请码系统 + 埋点 |
| **3. 7 日活跃** | `funnel_step3_active_7d` | 注册后 7 日内登录 ≥ 1 次 OR 任一 Skill 调用 | 注册后 Day 1-7 | 埋点 |
| **4. 30 日活跃** | `funnel_step4_active_30d` | 注册后 30 日内登录 ≥ 5 次 OR 任一 Skill 调用 ≥ 3 次 | 注册后 Day 1-30 | 埋点 |
| **5. 付费** | `funnel_step5_paid` | 用户完成支付 (trial_converted) | 注册后 Day 30-60 | 支付系统 (Stripe) |

### 1.2 漏斗目标 (PRD § 10.2 + § 11.2.1)

| 指标 | 目标 | 计算公式 |
|------|------|----------|
| **访问 → 试用** | ≥ 30% | step2 / step1 |
| **试用 → 7 日活跃** | ≥ 50% | step3 / step2 |
| **7 日活跃 → 30 日活跃** | ≥ 80% | step4 / step3 |
| **30 日活跃 → 付费** | ≥ 10% | step5 / step4 (但 PRD 总目标 = 试用 → 付费 5%+) |
| **总转化 (访问 → 付费)** | ≥ 1.5% | step5 / step1 |

> **PRD § 10.2.1.1 7 步漏斗 (主目标)**: 30 天试用 → 付费转化 30%+ (激活律师); 试用 → 激活 50%+
> **本表 5 步漏斗 (公测期跟踪)**: 访问 → 付费 1.5%+ (粗算) = 试用 → 付费 5%+ (符合 PRD 总目标)

## 2. 公测期首月 (7/26 - 8/23) 数据汇总表

> **更新方式**: 每日 BD 跑数据, 填入当日行. 周末 23:00 由 Mavis 跑周报汇总.
> **数据源 SQL** (W7 接入数据库后, Mavis 跑):

```sql
-- 漏斗 step1-5 数据
SELECT
  DATE(t1.created_at) AS day,
  COUNT(DISTINCT t1.user_id) AS step1_visit,
  COUNT(DISTINCT t2.user_id) AS step2_trial,
  COUNT(DISTINCT t3.user_id) AS step3_active_7d,
  COUNT(DISTINCT t4.user_id) AS step4_active_30d,
  COUNT(DISTINCT t5.user_id) AS step5_paid
FROM tracking t1
LEFT JOIN tracking t2 ON t1.user_id = t2.user_id AND t2.event = 'trial_register_submit'
LEFT JOIN tracking t3 ON t2.user_id = t3.user_id AND t3.event IN ('login','skill_run') AND t3.created_at <= t2.created_at + INTERVAL '7 days'
LEFT JOIN tracking t4 ON t3.user_id = t4.user_id AND t4.event IN ('login','skill_run') AND t4.created_at <= t2.created_at + INTERVAL '30 days'
LEFT JOIN tracking t5 ON t4.user_id = t5.user_id AND t5.event = 'payment_success'
WHERE t1.event = 'trial_landing_pv'
GROUP BY DATE(t1.created_at)
ORDER BY day;
```

## 4. 漏斗异常处理 (运营 SOP)

### 4.1 异常检测规则 (Mavis 跑日报时)

| 异常 | 触发条件 | 预警 |
|------|----------|------|
| **访问 → 试用 < 20%** | 单日 step2 / step1 < 20% (目标 30%+) | 红色预警 → BD 检查邀请码 + 落地页 |
| **试用 → 7 日活跃 < 40%** | 单日 step3 / step2 < 40% (目标 50%+) | 黄色预警 → 检查 onboarding 5 步 |
| **7 日 → 30 日活跃 < 60%** | 单日 step4 / step3 < 60% (目标 80%+) | 黄色预警 → 检查产品价值感 |
| **30 日付费 < 5%** | 单日 step5 / step4 < 5% (目标 10%+) | 红色预警 → 调整定价 / 付费墙 |

### 4.2 异常处理流程 (BD + 总指挥)

```
异常检测 (Mavis 跑数据) → 红色预警
  ↓ 1h 内
BD 初步诊断 (邀请码状态 / 落地页 / onboarding 步骤)
  ↓ 24h 内
总指挥拍板 (调整策略 / 紧急修复)
  ↓ 48h 内
修复 + 二次数据验证
  ↓ 7d 内
周报复盘 (写入 dashboard-w6.md §5)
```

### 4.3 公测期 5 个高风险场景 (预案)

| 场景 | 触发 | 应对 |
|------|------|------|
| **场景 1: 公测启动日 (7/26) 注册 < 30** | 当日 step2 < 30 | 朋友圈追加 1 条限时福利, 评审律师朋友圈帮转 |
| **场景 2: Day 7 留存 < 40%** | W7 末 step3 / step2 < 40% | 紧急修复 onboarding (lex-coder P0), BD 1v1 微信回访激活律师 |
| **场景 3: 创史体验官招满 100 但激活 < 50%** | W7 末 FM 注册 / FM 邀请码 < 50% | 创史正式资格延后到反馈, 加强客服群 (BD 1v1) |
| **场景 4: Day 30 付费转化 < 3%** | W8 末 step5 / step2 < 3% | 调整定价 (W9 折上折), 延后公测期 (8/30 截止) |
| **场景 5: 律协不批 100 席位** | 06-30 - 07-12 无批复 | 降级「律协背书 + 自营 60 创史」, W7 律协沙龙补足 |
