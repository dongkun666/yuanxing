## 5. 律师对三大功能的真实期待 (PRD 假设)

> 三大功能: AI 文书 / 类案检索 / 庭审准备
> 当前 = PRD §5 + outline §13 演示反应推演, 真实数据回填后细化

### 5.1 AI 文书草拟

**核心期待** (PRD §3 + outline §13 推演):
1. **速度**: 起诉状 3h → 1h, 律师函 2h → 30min
2. **质量底线**: 法条引用准确, 格式规范, 不能让主任改更多
3. **复用**: 同案由不同案情能复用 60%+ 内容, 只改关键事实
4. **本地化**: 客户信息不传出电脑
5. **风格学习**: 跟本所 / 本人风格学 (主任特别在意)

**风险担忧** (outline §12 推演):
- "AI 写得太正式, 没有律师个人风格" — 单飞在意
- "AI 写的法条是错的, 主任没看出来就出事" — 小所主任
- "AI 让助理失业, 我们律所文化不接受" — 小所

**W2 验证重点** (interview-02 §11):
- 主任对"团队风格统一" 的反应 (是加分 / 减分)
- 助理对"AI 帮我写初稿" 的反应 (是接受 / 担忧)

### 5.2 类案检索

**核心期待** (PRD §4.7 + Track E 假设):
1. **速度**: 检索耗时 <5min/次 (裁判文书网 30min+)
2. **匹配度**: 检索到的和本案案情匹配度 ≥70%
3. **裁判思路**: 不只列判例, 要给"法官倾向 + 论证逻辑"
4. **多维度过滤**: 案由 + 地域 + 时段 + 法院层级
5. **统计图表**: 支持率 / 金额 / 争议焦点 (可视化)
6. **中立呈现**: 严格禁用"胜诉率" / "案件预测" 等语言, 改用"支持率/统计参考"

**风险担忧**:
- "数据时效性, 旧判例不代表现在" — 老律师
- "AI 检索结果没法核实, 引用错了担责" — 主任
- "裁判文书网不开放接口, 数据不全" — 类案工具开发者

**W2 验证重点**:
- 律师对"严格中立语言" 的接受度 (是否会嫌"太绕")
- 律师对"统计图表" 的实操使用习惯 (是看还是跳过)

### 5.3 庭审准备

**核心期待** (PRD §3.2 + outline §8 推演):
1. **庭审提纲自动生成**: 根据起诉状 + 证据 + 类案 → 庭审提纲
2. **法条 + 判例引用清单**: 开庭前快速过, 避免漏引
3. **对方可能抗辩预测**: 基于类案 + 对方律师历史风格
4. **质证提纲**: 对对方证据的质证意见准备
5. **庭审录音转录 + 关键节点标记** (Phase 5+)

**风险担忧**:
- "庭审是门艺术, AI 准备的提纲太机械" — 出庭律师
- "对方临时变策略, AI 准备的就废了" — 资深律师

**W2 验证重点**:
- 庭审准备是不是真的痛点 (vs 文书和检索, 优先级?)
- 律师对"AI 庭审提纲"的实操期待 (是想要框架 / 还是详细到问话)
