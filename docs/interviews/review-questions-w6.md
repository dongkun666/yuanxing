## 1. 维度 1: 致命/重大/建议三级识别准确率 (D1, 30% 权重)

> **baseline 来源**: test-contracts-results.md (5 合同 baseline)
> **硬门槛**: ≥ 85% 准确率 = D1 ≥ 4.25, 一票否决 (漏检 ≥ 2 个 fatal = 不通过)
> **评分公式** (scoring-rubric.md §2.5): D1 = 致命(40%) + 重大(40%) + 建议(20%)

### Q1 [L1 单飞] — 致命风险识别 (租房合同)
**问题**: "在房屋租赁合同 baseline 中, Skill 2 标出 clause 3 (租金及支付) 违约金日 5% 为 fatal, 因为超过司法保护 LPR × 1.5 倍. 请问您认为这条 fatal 标得对吗? 如果不对, 您会判为什么级别?"

- **对照 baseline**: test-contracts-results.md §2.1 (合同 #1 房屋租赁, clause 3 fatal)
- **期望回答**: L1 (民商单飞) 应判 fatal, 法条依据 = 民法典第 585 条 + 最高法违约金司法保护上限
- **评分**:
  - 5 = 明确 fatal, 引用法条 + 司法保护 LPR × 1.5 倍
  - 4 = 判 fatal, 法条引用正确但未提 LPR 倍数
  - 3 = 判 major (低判 1 级)
  - 2 = 判 advisory (低判 2 级)
  - 1 = 漏检或判 ok

### Q2 [L2 小所合伙人] — 重大风险识别 (借款合同)
**问题**: "在个人借款合同 baseline 中, Skill 2 标出 clause 3 (利息) 利率超过 LPR × 4 倍为 major, 担保条款又约定了'逾期利息 + 违约金 + 罚息' 三重叠加. 请问您认为 Skill 2 是否正确识别了'三重叠加'的隐性风险? 您在实务中会怎么标注?"

- **对照 baseline**: test-contracts-results.md §2.2 (合同 #2 借款, clause 3 + clause 5 担保叠加)
- **期望回答**: L2 (小所主任, 民商) 应判 major, 关注"利滚利" + "砍头息" 隐性风险
- **评分**:
  - 5 = 判 major + 识别"三重叠加" + 引用最高法民间借贷司法解释第 30 条
  - 4 = 判 major, 但未明确指出"叠加" 风险点
  - 3 = 判 advisory (低判)
  - 2 = 漏检叠加风险
  - 1 = 完全漏检

### Q3 [L3 小所婚姻家事] — 建议风险识别 (服务合同)
**问题**: "在 App 开发服务合同 baseline 中, Skill 2 在 clause 4 (知识产权归属) 标了 1 个 advisory (源码归属表述模糊). 律师您在婚姻家事业务中, 类似条款 (如夫妻共同财产协议中的产权归属) 也会出现模糊表述. 请问您对这种'advisory' 级别提示是怎么看的? 律师客户能接受吗?"

- **对照 baseline**: test-contracts-results.md §2.4 (合同 #4 服务, clause 4 advisory)
- **期望回答**: L3 (婚姻家事) 应认为 advisory 必要, 实务中产权归属模糊确实导致纠纷
- **评分**:
  - 5 = 认为 advisory 必要 + 客户接受 + 建议补充条款
  - 4 = 认为必要, 客户可能嫌多
  - 3 = 认为部分必要, 建议精简
  - 2 = 认为过度提示, 客户会烦
  - 1 = 认为无必要

### Q4 [L4 中所合伙人] — 综合三级 + 批量 (5 合同总览)
**问题**: "评审 #1 您已独立审查过 5 合同, 现在总览一下: Skill 2 标出 4 fatal / 4 major / 14 advisory / 9 ok, 请问您跟 Skill 2 的 fatal/major 标注一致性如何? advisory 是否过度?"

- **对照 baseline**: test-contracts-results.md §2 (5 合同汇总表)
- **期望回答**: L4 (金融商事) 应给出一致性百分比 + 过度 advisory 数量
- **评分**:
  - 5 = fatal 一致 ≥ 95% + major 一致 ≥ 85% + advisory 过度 ≤ 1
  - 4 = fatal ≥ 90% + major ≥ 80% + advisory 过度 ≤ 2
  - 3 = fatal ≥ 85% + major ≥ 70% + advisory 过度 ≤ 3
  - 2 = fatal ≥ 80% (硬门槛边缘)
  - 1 = fatal < 80% (一票否决)

### Q5 [L5 企业法务] — 致命漏检审计 (5 合同对照)
**问题**: "作为企业法务, 您 1 个月审 100+ 合同, 假设 Skill 2 漏检 1 个 fatal (例如房屋租赁的'管辖条款单方住所地'), 您所在公司的合规审计能容忍这种漏检吗? 容忍率是多少 (例如 < 5%)?"

- **对照 baseline**: test-contracts-results.md §2.1 (合同 #1 clause 7 管辖 = major, 假设漏检)
- **期望回答**: L5 (法务总监) 应给出明确容忍率, 通常 < 5% 即合规要求
- **评分**:
  - 5 = 容忍率 < 3% + 要求复核机制 (人审 + AI 双轨)
  - 4 = 容忍率 < 5% + 要求审计日志
  - 3 = 容忍率 < 10% (偏松)
  - 2 = 容忍率 < 20% (过松)
  - 1 = 不能容忍任何漏检 (Skill 必须 100%)

## 2. 维度 2: 修改建议实用性 (D2, 25% 权重)

> **评分细则** (scoring-rubric.md §3): 质量 60% (法条准确 + 行业适配 + 模板可替换) + 覆盖度 40%
> **软门槛**: ≥ 70% 律师认可, D2 ≥ 4.0

### Q6 [L1 单飞] — 修改建议可执行性 (租房合同)
**问题**: "在房屋租赁合同 baseline 中, Skill 2 对 clause 3 (违约金日 5%) 给出修改建议'按 LPR × 1.5 倍调整' + modified_clause_template. 请问这条建议, 您在跟客户沟通时, 能不能直接采用? 还需要改什么?"

- **对照 baseline**: test-contracts-results.md §3.1 (合同 #1 建议)
- **期望回答**: L1 (单飞民商) 应评判建议是否可直接采用, 是否补充具体表述
- **评分**:
  - 5 = 直接采用 + 法条引用准确 + modified_clause_template 完整
  - 4 = 直接采用, 法条引用准确但表述需微调
  - 3 = 需改 30-50%, 法条准确但表述脱行业
  - 2 = 需改 > 50%, 法条有 1 处错误
  - 1 = 完全弃用, 法条错误 ≥ 2 处

### Q7 [L2 小所合伙人] — 修改建议覆盖度 (借款合同)
**问题**: "在个人借款合同 baseline 中, Skill 2 对 fatal/major 4 处全部给了修改建议, 其中 3 处带 modified_clause_template. 请问作为小所主任, 您审这类合同时, 这种'致命 100% 覆盖'对您价值大吗? 您希望建议覆盖到什么程度?"

- **对照 baseline**: test-contracts-results.md §3.2 (合同 #2 建议覆盖)
- **期望回答**: L2 应评判覆盖度 + 是否满足实务
- **评分**:
  - 5 = 覆盖 100% + 模板 ≥ 80% fatal + 节省 50% 审核时间
  - 4 = 覆盖 100% + 模板 60-80% + 节省 30-50% 时间
  - 3 = 覆盖 100% + 模板 < 60% + 节省 < 30% 时间
  - 2 = 覆盖 < 100% fatal (P0 缺陷)
  - 1 = fatal 漏 ≥ 2 处 (一票否决)

### Q8 [L3 小所婚姻家事] — 修改建议表述专业性 (服务合同)
**问题**: "在 App 开发服务合同 baseline 中, Skill 2 对 clause 5 (验收条款) 给出修改建议'补充验收标准 + 验收期限 + 验收异议期'. 您认为这种'具体表述 + 时间数字' 的建议, 律师客户 (尤其婚姻家事当事人) 能理解吗? 需不需要补充'通俗解释'?"

- **对照 baseline**: test-contracts-results.md §3.4 (合同 #4 建议)
- **期望回答**: L3 (婚姻家事) 应评判客户可读性, 可能需要通俗版
- **评分**:
  - 5 = 直接采用 + 不需要通俗解释 (律师本人过滤)
  - 4 = 直接采用, 律师补充一句客户解释
  - 3 = 律师需重写 30% + 增加通俗版
  - 2 = 律师需重写 > 50% + 客户看不懂
  - 1 = 不可用

### Q9 [L4 中所合伙人] — 修改建议行业适配 (销售合同)
**问题**: "在设备买卖合同 baseline 中, Skill 2 对 clause 3 (付款方式) 给出修改建议'30/30/30/10 比例 + 质保金 10%'. 您作为金融商事合伙人, 设备/工程行业惯例跟这建议匹配吗? 不同行业 (如 IT 服务 vs 房屋租赁) 违约金惯例差异, Skill 2 能识别吗?"

- **对照 baseline**: test-contracts-results.md §3.5 (合同 #5 建议)
- **期望回答**: L4 (金融商事) 应评判行业适配 + 跨行业识别
- **评分**:
  - 5 = 行业适配 100% + 跨行业自动识别
  - 4 = 行业适配 80% + 需手动选行业
  - 3 = 行业适配 60% + 偶尔脱行业
  - 2 = 行业适配 40% + 常脱行业
  - 1 = 无行业适配

### Q10 [L5 企业法务] — 修改建议法条准确性 (5 合同总览)
**问题**: "评审 #1 您已审过 5 合同 baseline, Skill 2 引用的法条 (民法典/民诉法/劳动法) 准确率如何? 您在公司合规审计中, 法条错误容忍率是多少?"

- **对照 baseline**: test-contracts-results.md §3 (5 合同法条引用统计)
- **期望回答**: L5 应给出法条准确率 + 公司容忍率
- **评分**:
  - 5 = 法条准确率 ≥ 95% + 容忍率 < 2%
  - 4 = ≥ 90% + 容忍率 < 5%
  - 3 = ≥ 80% + 容忍率 < 10%
  - 2 = ≥ 70% + 容忍率 < 20% (P0 改进)
  - 1 = < 70% (一票否决)

## 3. 维度 3: 谈判策略可执行性 (D3, 20% 权重)

> **评分细则** (scoring-rubric.md §4): 优先级排序 + 筹码描述 + 红线识别
> **软门槛**: ≥ 65% 律师认可, D3 ≥ 3.25

### Q11 [L1 单飞] — 谈判策略优先级 (租房合同)
**问题**: "在房屋租赁合同 baseline 中, Skill 2 给出 priority_clauses (3 条 fatal/major) + leverage_points (3 条) + walk_away_signals (2 条). 请问您在跟客户沟通时, 这个'优先级 + 筹码 + 红线' 三层结构, 客户能理解吗? 您会怎么排序?"

- **对照 baseline**: test-contracts-results.md §4.1 (合同 #1 谈判策略)
- **期望回答**: L1 应评判三层结构是否直观 + 是否需要简化
- **评分**:
  - 5 = 三层结构清晰 + 客户理解 + 按建议排序
  - 4 = 清晰, 客户理解, 律师补充背景
  - 3 = 清晰但客户嫌多, 律师精简
  - 2 = 不清晰, 律师重写
  - 1 = 不可用

### Q12 [L2 小所合伙人] — 谈判策略筹码描述 (借款合同)
**问题**: "在借款合同 baseline 中, Skill 2 给出 leverage_point '对方担保物价值 200 万, 借款金额 50 万, 担保覆盖充足, 可要求降低利率'. 请问这种'数据 + 理由' 描述, 您在谈判时能用得上吗? 需不需要补充'谈判话术'?"

- **对照 baseline**: test-contracts-results.md §4.2 (合同 #2 谈判筹码)
- **期望回答**: L2 应评判筹码描述 + 是否需要话术
- **评分**:
  - 5 = 直接用 + 数据说服力强 + 不需要话术
  - 4 = 直接用, 律师补充一句开场白
  - 3 = 律师需补充 1-2 句, 数据 OK
  - 2 = 数据不准 + 律师重写
  - 1 = 完全弃用

### Q13 [L3 小所婚姻家事] — 谈判策略红线识别 (服务合同)
**问题**: "在服务合同 baseline 中, Skill 2 给出 walk_away_signal '验收不通过超过 3 次 = 对方违约, 可终止合同'. 请问在您婚姻家事业务中, 类似'红线识别' (如对方出轨 = 可主张离婚 + 损害赔偿) 价值如何? AI 能自动识别吗?"

- **对照 baseline**: test-contracts-results.md §4.4 (合同 #4 红线)
- **期望回答**: L3 应评判红线识别在婚姻家事的延伸价值
- **评分**:
  - 5 = 婚姻家事红线自动识别 + 价值高
  - 4 = 价值高, 但需定制婚姻家事模板
  - 3 = 价值中, 部分红线能识别
  - 2 = 价值低, 婚姻家事偏个案
  - 1 = 无价值, 律师完全靠经验

### Q14 [L4 中所合伙人] — 批量谈判策略汇总 (5 合同)
**问题**: "假设您 1 个月审 50 合同, 每份合同的谈判策略 (priority + leverage + walk_away) 都不一样. 请问您需要一个'批量汇总'视图吗? 比如'本月 50 合同, 高风险条款 Top 10, 共同让步空间 Top 5, 共同红线 Top 3'?"

- **评分**:
  - 5 = 必须有批量视图 + 价值高 (节省 30%+ 谈判准备时间)

  - 3 = 部分价值, 律师手动汇总
  - 2 = 价值低, 每案不同
  - 1 = 无价值

### Q15 [L5 企业法务] — 跨部门谈判策略 (销售合同)
**问题**: "在设备买卖合同 baseline 中, Skill 2 给出'业务部门希望快速签约, 法务部希望降低风险' 的双方视角. 请问您作为企业法务, 这种'内部 + 外部' 双视角的谈判策略, 跨部门沟通中能用吗? 业务部门会接受吗?"

- **对照 baseline**: test-contracts-results.md §4.5 (合同 #5 跨部门)

- **评分**:

  - 3 = 双视角 + 业务部门嫌复杂
  - 2 = 仅外部视角 + 业务部门不买账
  - 1 = 无双视角 + 法务被当橡皮图章

## 4. 维度 4: LLM 输出中立性 (D4, 15% 权重)

> **硬门槛** (scoring-rubric.md §5): 0 违规"必败/必胜"等确定性预测, 一票否决
> **PRD §5.7 硬约束**: 类案界面禁用"胜诉率", 严格中立

### Q16 [L1 单飞] — "胜诉率" 表述审查 (5 合同总览)
**问题**: "评审 #1 您审过 5 合同 baseline, 请问 Skill 2 输出中有无'该合同必败/必胜/胜诉率 X%' 等确定性表述? 您作为律师, 对这种表述的态度是?"

- **对照 baseline**: test-contracts-results.md §5 (5 合同 LLM 输出中性度审计)
- **期望回答**: L1 应明确 0 违规 + 律师执业纪律要求
- **评分**:
  - 5 = 0 违规 + 表述严格中立 + 律师满意
  - 4 = 0 违规 + 1-2 处模糊 (如"较大概率为甲方胜诉"), 律师提示
  - 3 = 0 违规 + 多处模糊, 律师建议改进
  - 2 = 1 处明确违规 (如"必败"), 触发 P0 修复
  - 1 = ≥ 2 处违规 (一票否决)

### Q17 [L2 小所合伙人] — "司法保护" 表述审查 (借款合同)
**问题**: "在借款合同 baseline 中, Skill 2 给出'按 LPR × 1.5 倍司法保护上限' 表述, 请问这种表述准确吗? 律师客户看到'司法保护' 这种字眼, 会不会误解为'胜诉保证'?"

- **对照 baseline**: test-contracts-results.md §5.2 (合同 #2 中立性)
- **期望回答**: L2 应评判"司法保护" 表述准确性 + 客户误解风险
- **评分**:
  - 5 = 表述准确 + 无误解 + 客户清楚"司法保护" ≠ "胜诉保证"
  - 4 = 准确, 律师需解释 1 句
  - 3 = 表述偏模糊, 客户可能误解
  - 2 = 表述有歧义, 触发 UI 提示
  - 1 = 表述明确违规

### Q18 [L3 小所婚姻家事] — "建议争取" 表述审查 (服务合同)
**问题**: "在服务合同 baseline 中, Skill 2 给出'建议争取知识产权归属' 的修改建议. 请问这种'建议争取' 的表述, 在您婚姻家事业务中, 律师客户可能解读为'一定能争取到' 吗? 需不需要改成'建议明确约定'?"

## 6. 评分汇总模板 (律师填表)

> **每位律师填 1 份**, 5 律师 = 5 份, 评审结束后汇总到 lawyer_review_skill2_summary.md

### 6.1 评分量表 (5 分制, 跟 scoring-rubric.md §1.2 对齐)

| 分值 | 含义 |
|---|---|
| 5 | 优秀 (超出预期, 立即商用, 愿意推荐同事) |
| 4 | 通过 (达到预期, 愿意实务使用) |
| 3 | 及格 (基本可用, 律师能用但会手动调整) |
| 2 | 不及格 (明显缺陷, 律师用得不放心, 需重大调整) |
| 1 | 失败 (完全不可用, 律师弃用, 需重新设计) |

### 6.2 综合评分计算公式

```
综合评分 = 0.30 × D1 + 0.25 × D2 + 0.20 × D3 + 0.15 × D4 + 0.10 × D5
通过条件:
  - 综合评分 ≥ 4.0
  - D1 (致命/重大准确率) ≥ 4.25 (硬门槛)
  - D4 (中立性) = 5 (硬门槛, 0 违规)
  - D2 (实用性) ≥ 4.0 (软门槛, ≥ 70% 律师认可)
  - D3 (谈判策略) ≥ 3.25 (软门槛, ≥ 65% 律师认可)
```

### 6.3 一票否决项 (硬门槛)

| 项 | 触发条件 | 后果 |
|---|---|---|
| **中立性违规** | Skill 输出含"合同必败/必胜" 等确定性预测 | 综合 = 0, 评审不通过 |
| **致命风险漏检** | 5 合同中漏检 ≥ 2 个 fatal | D1 ≤ 2, 评审不通过 |
| **法条引用错误** | 引用的法条已被废止 / 编号错误 | D2 ≤ 2, 触发 P0 改进 |
| **数据泄露** | 评审过程中客户合同明文上传到云端 | 安全事件, 评审立即终止 |
