## 2. 用户画像对照 (PRD §3) — 4 类

| 维度 | 单飞律师 (§3.2) | 小型精品所 (§3.3) | 中大所 (§3.4) | 公司法务 (§3.5) |
|---|---|---|---|---|
| 年龄 | 30-50 岁 | 35-50 岁合伙人 | 40-55 岁主任 | 30-50 岁总监 |
| 执业年限 | 3-10 年 | 主任 8-20 年 | 主任 15-25 年 | 法务 5-15 年 |
| 团队 | 无 / 1-2 助理 | 主任 + 1-3 授薪 + 1-2 助理 | 主任 + 3 合伙人 + 10 授薪 + 5 助理 | 总监 + 3-5 法务经理 + 5-10 专员 |
| 业务 | 民商为主 | 综合性 (民商+刑事+行政) | 综合性, 多专业部门 | 合同审查 + 合规 + 诉讼 + 知产 |
| 日案牍 | 4-6h | 主任 2-3h + 授薪 5-6h + 助理 6-8h | 主任 5-8h/周 (审核) + 授薪 5-6h/天 | 总监 8-12h/周 (审查) + 专员 5-7h/天 |
| 年/月预算 | ¥200-500/月 | ¥1000-3000/月 (整体) | ¥50 万+/年 (整体) | ¥10-50 万/年 (法务部) |
| 主要痛点 | 时间全在案牍, 类案检索慢 | 助理人效低, 审核陷死 | 多套工具不联通, 团队协同混乱, 案件风险难把控 | 合同审查量大, 合规风险点多 |
| LexPrime 帮他 | 起诉状 3h→1h, 证据目录 2h→30min | 提升助理人效 50%, 律师本人减少案牍审核 | 一体化平台, 团队协同 + 知识共享 + 风险驾驶舱 | 合同审查自动化, 合规风险驾驶舱 |

**核心假设 (待验证)**:
- 单飞最痛 = 个人效率瓶颈 (文书 + 检索)
- 小所最痛 = 团队协同 + 助理人效 + 主任审核负担
- 中大所最痛 = 工具碎片化 + 案件风险难把控 + 知识沉淀
- 公司法务最痛 = 合同审查量大 + 合规风险 + 跨部门协同 + 数据安全 (私有化诉求)
- **W3 验证重点**: §11 演示反馈中, 4 类用户对 LexPrime 的反应差异 (单飞/小所重个人提效, 中大所/公司法务重团队一体化)

## 5. 律师/法务对四大功能的真实期待 (PRD 假设)

> 四大功能: AI 文书草拟 / 类案检索 / 庭审准备 / 合同审查
> 当前 = PRD §5 + outline §13 演示反应 + Skill 1/2 推演
> 真实数据回填后细化

### 5.1 AI 文书草拟 (跨 4 类)

**核心期待** (PRD §3 + outline §13 推演):
1. **速度**: 起诉状 3h → 1h, 律师函 2h → 30min
2. **质量底线**: 法条引用准确, 格式规范, 不能让主任/总监改更多
3. **复用**: 同案由不同案情能复用 60%+ 内容, 只改关键事实
4. **本地化**: 客户信息不传出电脑
5. **风格学习**: 跟本所 / 本人风格学 (主任/总监特别在意)
6. **【W3 新增】法务视角**: 合同审查专用模板 (致命/重大/建议三级)

**风险担忧** (outline §12 推演):
- "AI 写得太正式, 没有律师个人风格" — 单飞在意
- "AI 写的法条是错的, 主任没看出来就出事" — 小所主任 / 中大所主任
- "AI 让助理失业, 我们律所文化不接受" — 小所
- "AI 答错, 公司担责" — 公司法务最敏感

**W3 验证重点** (interview-03 §11 + interview-04 §11):
- 主任对"全所统一文书风格" 的反应 (是加分 / 减分)
- 总监对"AI 合同审查致命/重大/建议" 的反应 (是合理 / 太粗 / 太细)

### 5.2 类案检索 (跨 4 类)

**核心期待** (PRD §4.7 + Track E 假设 + Skill 1 W7 交付):
1. **速度**: 检索耗时 <5min/次 (裁判文书网 30min+)
2. **匹配度**: 检索到的和本案案情匹配度 ≥70%
3. **裁判思路**: 不只列判例, 要给"法官倾向 + 论证逻辑"
4. **多维度过滤**: 案由 + 地域 + 时段 + 法院层级
5. **统计图表**: 支持率 / 金额 / 争议焦点 (可视化)
6. **中立呈现**: 严格禁用"胜诉率" / "案件预测" 等语言, 改用"支持率/统计参考"
7. **【W3 新增】合规处罚类案维度** (公司法务强需)
8. **【W3 新增】行业类案** (公司法务强需, 律所律师次要)

**风险担忧**:
- "数据时效性, 旧判例不代表现在" — 老律师
- "AI 检索结果没法核实, 引用错了担责" — 主任/总监
- "裁判文书网不开放接口, 数据不全" — 类案工具开发者
- "合规处罚类案数据从哪来, 准吗" — 公司法务

**W3 验证重点** (interview-03 §5.1 + interview-04 §5.1):
- 中大所主任对"全所推广" 的决策
- 公司法务总监对"合规处罚类案维度" 的接受度
- 4 类用户对"中立语言" 的接受度 (是否会嫌"太绕")

### 5.3 庭审准备 (跨 4 类, 中大所/公司法务委托律师为主)

**核心期待** (PRD §3.2 + outline §8 推演):
1. **庭审提纲自动生成**: 根据起诉状 + 证据 + 类案 → 庭审提纲
2. **法条 + 判例引用清单**: 开庭前快速过, 避免漏引
3. **对方可能抗辩预测**: 基于类案 + 对方律师历史风格
4. **质证提纲**: 对对方证据的质证意见准备
5. **庭审录音转录 + 关键节点标记** (Phase 5+)

**风险担忧**:
- "庭审是门艺术, AI 准备的提纲太机械" — 出庭律师
- "对方临时变策略, AI 准备的就废了" — 资深律师
- "【W3 新增】公司案件委托律师, 法务不参与庭审" — 公司法务

**W3 验证重点** (interview-03 §11 + interview-04 §11):
- 中大所/小所对"庭审提纲" 的实操期待 (想要框架 / 还是详细到问话)
- 公司法务对"庭审准备" 的优先级 (低, 委托律师) vs "合同审查" (高)

### 5.4 【W3 新增】合同审查 (公司法务核心 + 小所/中大所次要)

**核心期待** (PRD §3.5 + Skill 2 假设):
1. **速度**: 标准合同 30-90min → <10min (致命/重大/建议三级分类)
2. **风险高亮**: 致命红 / 重大黄 / 建议蓝, 一眼可见
3. **修改建议**: 给具体修改建议, 不只标记风险
4. **谈判策略**: 给对方可能的还价空间 + 我方底线建议
5. **模板匹配**: 自动识别合同类型, 套用本所/本公司模板
6. **一键导出**: Word / PDF 审查报告
7. **【W3 新增】批量审查**: 1000+ 件合同分批处理 (公司法务硬需)
8. **【W3 新增】与现有 CLM 系统集成** (公司法务可能已有自研)

**风险担忧** (interview-04 §12 推演):
- "AI 答错, 公司担责" — 公司法务最敏感
- "AI 替代基础审查, 律师会失业" — 律师协会
- "AI 不懂我司业务, 修改建议太空" — 法务总监

**W3 验证重点** (interview-04 §11.5):
- 致命/重大/建议三级分类是否合理 (太粗 / 太细)
- 修改建议实用性 (能用 / 需要律师改 / 太机械)
- 谈判策略弹窗 (有用 / 多余 / 想要更多场景)
- 一键导出审查报告 (能用 / 想要更多格式 / 不需要)
